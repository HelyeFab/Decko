> **LOGIC:** When building a specific surface, first check `design-system/decko/pages/[surface].md`.
> If that file exists, its rules **override** this Master file. Otherwise, follow the rules below.
>
> **Stack:** Flutter (Material 3, `useMaterial3: true`). This is a mobile app, **not** a web/marketing site —
> there are no landing pages, pricing tiers, CSS, hover states or `cursor:pointer` here.

## Design Personality

Warm, friendly, calm, and a little playful — a study space that feels inviting rather than clinical.
The *sensibility* the ui-ux-pro-max engine suggested (soft, rounded, "claymorphic" friendliness) is right;
Decko expresses it through **flat Material 3 surfaces with generous rounding and soft seed-tinted colour**,
not heavy double-shadow clay. Keep depth subtle: elevation `0`, transparent surface tint, big radii.

Reserve more overt "toy-like" playfulness for the **`game` card style** and gamification moments
(XP, streaks, achievement badges) — not the everyday chrome.

---

## Color — use the theme, never hard-code

Decko ships **three app themes**, each built from a single seed via `ColorScheme.fromSeed` in
`ThemeRegistry._build`. **Soft Study is the signature/default.** Always read colours from
`Theme.of(context).colorScheme` (`primary`, `surface`, `onSurface`, `outlineVariant`,
`surfaceContainerHighest`, …) — never paste hex into widgets.

| App theme | id | Brightness | Seed | Scaffold | Surface |
|-----------|------|-----------|------|----------|---------|
| **Soft Study** (default) | `soft-study` | light | `#E0785A` warm terracotta | `#F7F2EA` cream | `#FFFBF5` |
| Decko Light | `decko-light` | light | `#4F6BED` indigo | `#F4F6FB` | `#FFFFFF` |
| Decko Dark | `decko-dark` | dark | `#8AA2FF` | `#14161C` | `#1E212B` |

> Note: ui-ux-pro-max proposed an indigo `#4F46E5` + green palette. That only matches the **Decko Light**
> alt theme — it is *not* Decko's identity. The signature is **warm terracotta (Soft Study)**.
> **Dark mode is a first-class theme, not an anti-pattern.** Do not "avoid dark mode" here.

**Adding a theme:** add an `AppThemeConfig` to `ThemeRegistry.appThemes` with a new seed — do not
restyle individual screens.

## Typography

Material 3 `TextTheme` from the active `ThemeData`. Decko currently uses the platform default family
(no `google_fonts` dependency) — keep it that way unless a font is added centrally to `_build`.
Japanese readings render through `DeckoFieldContent` / `furigana_text.dart`, so any future font choice
**must** carry full CJK + furigana coverage. (The engine's "Baloo 2 / Comic Neue" pick is Latin-only —
do not adopt it for card content.)

## Component Conventions (from `ThemeRegistry._build` — already centralised)

Style components by extending the theme, **not** by per-widget overrides:

- **Surfaces / cards:** `Card` → `elevation: 0`, transparent `surfaceTint`, shape radius `DeckoRadii.lg` (22),
  colour = `surface`. Prefer the shared `DeckoCard` for flashcards; `Card` for list/detail tiles.
- **Primary action:** `FilledButton` — full-width feel via `minimumSize: Size.fromHeight(56)`,
  text `16 / w600`, radius `DeckoRadii.md` (16).
- **Secondary action:** `OutlinedButton` — same height/shape, side = `outlineVariant`.
- **App bar:** flat — `elevation: 0`, transparent tint, `centerTitle: false`, scaffold-coloured.
  Use the shared `DeckoAppBar`.
- **Chips / tags:** pill-shaped (`DeckoRadii.pill`), `surfaceContainerHighest`, no border.
- **Navigation:** `DeckoBottomNav`.
- **Dialogs / toasts:** `DeckoConfirmDialog`, `DeckoSnackbar`.
- **Section labels:** `SectionHeader`.
- **Gamification:** `AchievementBadge`, `PromiseTile`.

## Card Themes (separate from app themes — DEC-004)

A learner pairs any app shell with any card look. Rendered by `DeckoCard`, which **flips** front→back
(3D rotation, ~460ms) — it does not grow taller. Front = prompt + audio; back = meaning, reading, image,
example. Styles (`CardThemeStyle`):

| Style | id | Intent |
|-------|------|--------|
| `minimal` | `minimal` | Large prompt, minimal chrome, maximum focus (default). |
| `detailed` | `detailed` | Reading, meaning, example, tags laid out clearly. |
| `game` | `game` | Playful treatment for challenge rounds / XP feedback — the place to lean into clay/bubbly. |

## Key Surfaces (replaces the engine's irrelevant "landing page" pattern)

Design these real screens; each can get a `pages/[name].md` override:

- `deck_library` — browse/import decks (home)
- `deck_detail` / `deck_options` — a deck's cards & study settings
- `review_session` — the core flip-and-rate loop + `session_summary`, `rating_button_row`
- `progress` — XP, streaks, daily goals, completion feedback
- `themes` — the app/card theme gallery (`theme_gallery_screen`)
- `import` / `imported_source` — deck import preview
- `settings` — study profiles, global study options

## Motion

- Card flip ~460ms (existing). Micro-interactions 150–300ms.
- Animate cheaply (opacity/transform); honour reduced motion via `MediaQuery.disableAnimations` /
  `AccessibilityFeatures`.

## Anti-Patterns (Decko-specific — corrected from generic output)

- ❌ Hard-coded hex / magic numbers in widgets → use `ColorScheme` + `DeckoSpacing`/`DeckoRadii`.
- ❌ Per-screen restyling → extend `ThemeData` in `ThemeRegistry._build`.
- ❌ Emojis used as icons → use `Icons.*` (Material) consistently.
- ❌ Latin-only fonts for card content → must cover Japanese + furigana.
- ❌ Heavy skeuomorphic shadows on everyday chrome → keep surfaces flat (elevation 0).
- ❌ Complex/jargon-heavy copy → learner-friendly wording.
- ~~❌ Dark mode~~ → **Decko ships `Decko Dark`. Dark mode is supported, not forbidden.**

- [ ] Looks correct in **all three** app themes (Soft Study, Decko Light, Decko Dark).
- [ ] Touch targets ≥ 48dp; `FilledButton`/`OutlinedButton` keep the 56px height rhythm.
- [ ] `Semantics` labels on icon-only buttons; meaningful images labelled.
- [ ] Text contrast ≥ 4.5:1 against its surface in every theme.
- [ ] Reduced-motion respected.
- [ ] Japanese fields render furigana correctly via `DeckoFieldContent`.
- [ ] No new state-management dependency (ValueNotifier pattern is deliberate; a full SM library is a non-goal).
